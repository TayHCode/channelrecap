# Output format

One folder holds one library. `prepare` includes all finished videos in its
`library.json`, ordered by ascending publication date when every video has one
(ties use manifest order), otherwise by manifest order. No file records a generation
time. JSON uses UTF-8, two-space indentation and a trailing newline.

## Files

| Path | Contents |
|---|---|
| `summary.md` | Video inventory; frequent, recurring and unique terms; questions and deferrals; filler totals and trends; failed rows and limits. Hints are counts and excerpts, not conclusions. |
| `transcripts/<video-id>.txt` | One transcript with metadata headers and timestamped paragraphs. Quote this file. |
| `data/<video-id>.json` | Segment and word timing for tools and later versions. |
| `library.json` | Every video's identity, status, paths and settings. Updated atomically after each attempted row. |
| `fillers.csv` | Per-video totals and phrase counts. |
| `AGENT_PROMPT.md` | The bundled six-section analysis prompt. |
| `AGENTS.md`, `CLAUDE.md` | Pointers to that prompt for the user's agents. |
| `site-captions/<video-id>/` | Optional reference VTT copies from link sources; requested with `--save-site-captions`, never used for analysis. |
| `.cache/audio/`, `.cache/downloads/` | Temporary clips and downloads, removed by default. The keep flags retain them. |

Agent files are written only when absent or when their first line is
`<!-- generated by channelrecap -->`. Your own unmarked files are left alone with a
notice. `analysis.md` is written by your agent, not by channelrecap.

## Text transcript

Headers are `Title`, `Video id`, `Source`, `Date`, `Covered`, `Length`, `Words` and
`Language`, followed by `Timestamps show the time in the original video.` Source text
comes from the manifest; absolute and HOME-relative local paths use only the file name in this text file.
Failed-source labels in the summary follow the same rule, including Windows and file
URI sources. Free-form errors containing any slash, backslash, drive prefix or `file:`
notation are replaced in full by a fixed diagnostic that says local path details were
omitted. This deliberately also shortens some URL and non-path diagnostics; it avoids
leaking later components of unknown paths with spaces. Other errors are collapsed to
one line and capped at 500 characters. Older stored errors are sanitized when preparing
the summary. The local library index retains the original source for resume.
Unknown dates are blank. `Covered` is `whole video`, `HH:MM:SS to HH:MM:SS`,
`from HH:MM:SS`, or `up to HH:MM:SS`. Length is the transcribed duration. Words are
Unicode letters and digits with internal apostrophes retained.
Header fields are collapsed onto one line; metadata cannot create speech paragraphs.
Unicode captions, titles and local paths are preserved, including combining marks,
right-to-left scripts and emoji. Caption files accept UTF-8 (with or without BOM)
and BOM-marked UTF16. Unpaired surrogate code points are invalid text and produce an
expected input error with exit 2. Hint word positions map back to the original text even when
casefolding expands a character or changes word boundaries.

Paragraphs start with `[HH:MM:SS]` and have a blank line between them. Times are floored
to whole seconds. Segment text is joined with single spaces. Start a new paragraph
at the first segment, at a gap of at least two seconds, after at least 30 seconds when
the previous segment ends with `.`, `?` or `!`, or after at least 60 seconds regardless
of punctuation. Paragraph times are the first segment's start time.

## Transcript JSON

| Field | Meaning |
|---|---|
| `schema_version` | Integer format version, currently 1. |
| `video_id` | Stable identifier shared with the text file and library. |
| `language` | Speech language code, or caption language supplied by the user. |
| `language_probability` | Speech model's language confidence; null for captions. |
| `offset` | Selected source start in seconds, or zero. Already added to all segment and word times. |
| `duration` | Transcribed length in seconds, not the absolute source end time. |
| `segments` | Ordered list of segment objects. |

A segment has `start`, `end`, `text` and `words`. Each word has `start`, `end`, `word` and
`probability`. Word times may be null when the engine has no timing. Word probability
is null or a number from zero to one, rounded to five decimals; it is retained on
JSON round trips. Times are seconds in the original source, rounded to three decimals. Caption
segments have an empty `words` list. Hints and filler buckets use segment start times,
even when word times are available. Do not add `offset` a second time.
All listed fields are required. Duration, offset and segment times must be finite,
nonnegative numbers; word times may also be null (booleans are not numbers here). Confidence must be null or a
finite number from zero to one. Text must be valid Unicode without NUL bytes.
`prepare` and `fillers` validate every finished transcript before writing derived files;
invalid data exits 2 with an `error:` message.

## Library JSON

Top-level fields are `schema_version` (1), `tool` (`channelrecap`), `tool_version` and
`videos` (a list). Each video entry has:

| Fields | Meaning |
|---|---|
| `key`, `video_id` | Stable row key and file identifier; see the manifest reference. |
| `order` | Position in the latest manifest run that included this row. |
| `source`, `source_kind` | Input as supplied; kind is `media`, `link` or `captions`. |
| `title`, `date`, `language` | Display metadata; absent date is an empty string. |
| `start`, `end` | Requested source times; null when omitted. |
| `status`, `error` | `done` or `failed`; empty error on success, a message on failure. |
| `duration`, `words` | Transcribed length and total word count. |
| `transcript`, `data` | Paths relative to the output folder. |
| `transcription` | Engine and speech settings. |

Caption settings are `{"engine": "captions"}`. Media settings have `engine`
(`faster-whisper`), `model`, actual `device`, `compute_type` and `verbatim_hint`
(boolean, false unless `--verbatim-hint` is used). Failed entries may lack success-only fields. Resuming skips a done row
only when its transcript and data still exist. The same key retains its original id.
On POSIX, the atomic index and transcript files use restrictive file permissions.
On Windows, access follows the parent folder ACL; use a folder restricted to your account.
Derived outputs follow your
system's normal file-creation permissions; set a restrictive umask for private libraries.
With `--force`, a failed replacement marks the row failed and removes it from the
summary even though an earlier transcript may remain on disk. If every row fails,
`run` and `prepare` replace the summary with zero finished videos, an explicit notice,
and the current failures; filler output contains its header only. `prepare` exits 1;
`run` uses the failure class exit code documented in the README. Earlier
transcripts and data remain untouched as evidence. `transcribe` alone updates only
the transcript/index stage; use `prepare` afterwards to refresh derived files.
Keep a separate library
copy if you need to preserve a prior successful run while trying new settings.

Version 1 is the only schema this release reads. Unsupported versions are rejected;
incompatible changes will need a new version and an explicit migration path. Consumers
should inspect the version before interpreting fields.

## Filler CSV and summary hints

CSV columns, in order, are
`video_id,date,title,words,filler,ambiguous,sentence_start_only,count,per_1000_words`.
Each video begins with `TOTAL_CLEAR` and `TOTAL_ALL` rows, whose two flag fields are
empty. These are followed by entries with positive counts, largest counts first,
ties alphabetical; flags are `yes` or `no`. Rates are count times 1,000 divided by
word count, with one decimal place. Rate fields are blank for transcripts with
fewer than 20 words, including empty transcripts.
Text fields starting with spreadsheet formula markers or control whitespace receive
a leading apostrophe in the CSV so they open as text; stored titles are unchanged.

Matching uses casefolded words and normalizes curly apostrophes. Longest phrases win,
ties alphabetical; matched words are not counted again. `^` entries match only at a
sentence's first word. The busiest minute uses segment starts in source time and the
earliest minute on a tie. It counts all candidates, including ambiguous entries.

Topic hints count qualifying single words and pairs within a sentence. Words need
at least three characters and exclude numbers, stopwords and words in filler entries.
Frequent singles need three occurrences; pairs need two. Recurring terms occur at
least twice in each of at least two videos. Questions need four words and a question
mark. Unpunctuated text also yields explicitly labeled possible questions beginning
with an English question word. Hints are capped at 40 words and 280 characters plus
omission marks; deferral excerpts surround the matched phrase. Deferrals match bundled word sequences. None of these rules decides whether a
question was answered; the agent must read all transcripts.

Trends require three usable videos with at least 20 words each. Compare the means of the first and last halves, omitting
the middle video for odd lengths. A ratio at least 1.25 is rising, at most 0.75 falling,
otherwise steady. Two zero means are steady; a zero first mean with a positive last
mean is rising. Lists are capped: 15 frequent terms per video, 25 recurring terms,
five unique terms, 30 questions and 20 deferrals per video. Overflow counts are shown
for questions and deferrals. Summary table pipes are escaped and cell newlines removed.

## Strict findings and citations

The report is a small line-based format. Start with `# Video analysis`, then include
all six headings below in this order. Sections 1 through 5 are the findings block.
Every nonblank line there is one claim with one or more canonical citations:

```text
- Plain claim. | [video-id @ HH:MM:SS..HH:MM:SS | "exact words copied from the transcript"]
```

Use the video id from the summary. The range gives the paragraph timestamp where the
quote starts and the paragraph timestamp where it ends. Repeat the same timestamp
for a quote inside one paragraph. For a continuous quote across adjacent paragraphs,
join their text with one space and use the first and last paragraph timestamps.
These are paragraph locations, not precise word durations. Hours have at least two
ASCII digits; minutes and seconds each have two, below 60.

Copy the quote character for character, including case, punctuation and Unicode.
The checker requires at least four words; the prompt asks for five to 30. No case
folding, apostrophe replacement, spelling correction, ellipsis joins or paraphrases.
Escape a literal double quote as `\"` and a literal backslash as `\\` inside the
quoted field. Other escapes are not allowed. The quoted field is a JSON string.
Unicode quotation marks inside a verified quote are data, never alternate delimiters.

Claim prose uses only ASCII letters, digits, spaces and `. , ; : ! ? % -`. Write
names and non-ASCII speech inside the exact quoted field. Citations use precisely
the spaces and punctuation shown. Multiple citations follow on the same line,
separated by one space. No trailing text, indentation, tables, links, brackets,
footnotes, parentheticals, quote forms, Markdown emphasis or invisible characters
are allowed outside the canonical citations. Blank evidence sections are allowed.
There must be at least one verified citation in the whole report.

```text
# Video analysis
### 1. Topics and trends
### 2. Questions raised but not answered
### 3. Thin explanations
### 4. New video ideas
### 5. Speaking habits
### 6. What I could not determine
Note: These are unchecked limits or process notes, not findings.
```

Free prose outside the findings block must be a single `Note: ` line, either before
section 1 or in section 6, using the same prose alphabet. Notes are explicitly
unchecked context or limitations. Do not put findings, video claims or references
there; put every finding in sections 1 through 5 with its citations. Other headings,
bullets, continuations, comments and code fences fail, including after section 6.
An omitted, duplicate, misspelled or out-of-order heading fails. A malformed line
cannot close an evidence section or make later lines disappear.

This replaces the older free-form reports and blockquotes. Ask your agent to rewrite
an older report using the generated prompt; adding one valid citation cannot rescue
unparsed lines. `check-citations` consumes every line and reports its number on errors.
Statuses are `malformed`, `unknown-video`, `too-short`, `wrong-time` for a quote at
another paragraph range, and `not-found` for text absent from the transcript. Exit 0
requires the complete report grammar and all citations to verify. Invalid file
encoding is an input error with exit 2; report/evidence problems exit 1.

The checker verifies quotes and their paragraph ranges. It cannot prove a claim,
search coverage, a reported count, an inference or a proposal is correct. Review
reasoning yourself and check counts against `summary.md` and `fillers.csv`.

## Invalid inputs and recovery

Manifest fields, command arguments, prompt/filler files and pending captions must
contain valid Unicode without NUL. Validate them before any output or checkpoint
write; an invalid caption also leaves a previously good library unchanged. Correct
the input and retry. Ordinary caption errors such as no cues still fail only that
row. Transcript data and metadata use the same text validation on write and read.
An invalid speech result cannot replace a previous good transcript or index entry.
Invalid text returned by an external tool fails that row, allows later rows to run
unless `--fail-fast`, and makes the command exit 2. Successful row checkpoints remain.
This mid-batch case is different from input validation before processing starts.

If an earlier version already wrote bad metadata, fixing the source alone cannot
repair its saved index. Keep that entire folder as a backup. Correct your manifest
and caption inputs, then rebuild into a new, unused folder:

```sh
channelrecap run --manifest videos.csv --out repaired-library
channelrecap prepare --out repaired-library
```

Check the new summary and transcripts before switching to that folder. Copy your own
notes or agent instructions over only after reviewing them. Do not copy the damaged
`library.json` or `data/` files into the new folder. Rebuilding does not delete or
edit the damaged folder. Restoring a known good full backup is another option. With
media inputs this requires transcription again; original captions need no model.

## Speech eligibility and estimates

Finished rows remain `status: done`. `speech_status` is `usable`, `no_speech`, or
`too_few_words`; `trend_usable` is true only for transcripts with at least 20 words.
`notice` explains exclusions. Preparing an older library derives these fields from
its saved transcripts, so earlier silent rows cannot distort the new trends.
The summary lists retained transcripts and exclusions. CSV counts remain visible,
but per-1,000-word rate fields are blank for excluded rows. Topic and filler trend
series list usable rows only and require three usable videos.
Word and filler counts are estimates and can differ slightly across machines and
models. They do not establish an exact count of the original speech.
